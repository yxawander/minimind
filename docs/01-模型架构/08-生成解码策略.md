## 1. 原理

### 1.1 自回归生成与 KV Cache

语言模型一次 forward 只产出「下一个 token 的分布」。要生成 N 个 token，标准流程：

```
prompt = [t1..tm] ──forward──→ 选出 t(m+1)
prompt+[t(m+1)] ──forward──→ 选出 t(m+2)     ← 朴素做法：每次重算全部 m+k 个位置，O(S²) 总开销
```

**KV Cache 优化**：注意力里每个历史 token 的 K/V 与新 token 无关，算过一次就不用重算。缓存每层 (K,V) 后，第 k 步只 forward **1 个新 token**（q 长度 1，k/v 长度 past+1），复杂度 O(S²)→O(S)。

配合的两个机制（都在前面文档讲过）：

- RoPE 表按 `start_pos=past_len` 切片 → 新 token 带正确位置相位（03 篇）；
- Attention 手写路径处理 q=1、kv=past+1 的形状（04 篇 `-seq_len` 技巧）。

### 1.2 采样策略全家桶

拿到最后一个位置的 logits `[vocab]` 后，如何挑下一个 token？

| 策略 | 公式/操作 | 作用 |
|------|-----------|------|
| **temperature** | `logits / T` | T→0 逼近贪心（确定性），T=1 原始分布，T>1 更随机。softmax 前除温度改变分布尖锐度：`p_i ∝ exp(z_i/T)` |
| **greedy** | `argmax(logits)` | 完全确定性（do_sample=False 时） |
| **top-k** | 只保留得分最高的 k 个，其余置 −∞ | 掐掉长尾噪声词，k=50 常用 |
| **top-p (nucleus)** | 按累积概率达到 p 的最小词集内采样 | 词集大小随分布自适应：分布尖锐时集小，平坦时集大 |
| **repetition penalty** | 已出现 token：正分 ÷α、负分 ×α | 压低重复（原论文 CTRL：α>1 时除/乘），比硬 ban 更温和 |

实践顺序（本仓库实现顺序）：temperature 缩放 → repetition penalty → top-k 截断 → top-p 截断 → softmax → 多项式采样。

```python
        input_ids = kwargs.pop("input_ids", inputs).repeat(num_return_sequences, 1)
        attention_mask = attention_mask.repeat(num_return_sequences, 1) if attention_mask is not None else None
```

|----|------|
| 268 | streamer 先收到 prompt（前端可先显示输入） |
| 269-270 | 主循环最多生成 `max_new_tokens` 个。`past_len`：当前 Cache 长度（第 0 步为 0，之后每步 +1） |

| 行 | 讲解 |
|----|------|
| 273 | 只取**最后一个位置**的 logits `[B, vocab]`（前面位置的概率分布这一步用不到）。采样时先除温度；贪心模式跳过 |

```python
            if repetition_penalty != 1.0:
                for i in range(input_ids.shape[0]):
                    seen = torch.unique(input_ids[i]); score = logits[i, seen]; logits[i, seen] = torch.where(score > 0, score / repetition_penalty, score * repetition_penalty)
```

| 行 | 讲解 |
|----|------|
| 274-276 | **重复惩罚**（默认关，α=1.0 跳过）：逐条序列处理。<br>• `seen`：该序列**已出现过的全部 token id**（去重）；<br>• 对这些 token 的当前得分做「**正向压低**」：正分除以 α（>1 时变小），负分乘 α（>1 时更负）——统一效果是「让见过的词更不倾向被选中」。<br>• 为什么分正负处理？直接全乘 α 会让负分变得更负——那反而**更不会**被选中（softmax 里越小越不选），方向反了。除/乘的分法保证「无论符号都朝不选它的方向推」。<br>缺点：for 循环逐条处理，batch 大时略慢（实现透明优先） |

```python
            if do_sample and top_k > 0:
                logits[logits < torch.topk(logits, top_k)[0][..., -1, None]] = -float('inf')
```

| 行 | 讲解 |
|----|------|
| 277-278 | **top-k 截断**：`torch.topk(logits, k)[0]` 是每行前 k 大的值，`[..., -1, None]` 取「第 k 大」（门槛值）并保留维度用于广播；`logits < 门槛` 的位置全部置 −∞。softmax 后这些位置概率为 0。注意 k 大于词表时 topk 返回全体、无副作用 |

```python
            if do_sample and top_p < 1.0:
                sorted_logits, sorted_indices = torch.sort(logits, descending=True)
                mask = torch.cumsum(torch.softmax(sorted_logits, dim=-1), dim=-1) > top_p
                logits[mask.scatter(1, sorted_indices, F.pad(mask[..., :-1], (1, 0)))] = -float('inf')
```

| 行 | 讲解 |
|----|------|
| 279-282 | **top-p（nucleus）截断**，四步读：<br>1. 降序排序 logits；<br>2. 对排序后的 softmax 概率做**前缀累积和**；<br>3. `cumsum > top_p` 得到布尔掩码——「加上这个 token 后累积概率才超过 p」的位置为 True。**注意语义**：我们想保留的是「第一个超过 p 的位置」**及它之前**的所有位置；直接用 `mask` 会把那个跨界位置也剪掉，所以第 4 步修正；<br>4. `F.pad(mask[..., :-1], (1,0))`：把掩码整体**右移一位**（前缀和的超标位置右移后正好把「导致超标的那一项」保留下来，第一个位置恒为 False 保留）。再用 `scatter` 把右移后的掩码按 `sorted_indices`（从排序空间映射回词表空间）放回原位置，命中的置 −∞。<br>一句话：**保留累积概率刚好达到 p 的最小词集**。这是 HF 官方实现同款技巧 |

```python
            next_token = torch.multinomial(torch.softmax(logits, dim=-1), num_samples=1) if do_sample else torch.argmax(logits, dim=-1, keepdim=True)
```

| 行 | 讲解 |
|----|------|
| 283 | 最终采样：`softmax` 得概率 → `multinomial` 按概率抽 1 个（带随机性）；贪心模式直接 `argmax`。输出 `[B, 1]` |

```python
            if eos_token_id is not None: next_token = torch.where(finished.unsqueeze(-1), next_token.new_full((next_token.shape[0], 1), eos_token_id), next_token)
            input_ids = torch.cat([input_ids, next_token], dim=-1)
            past_key_values = outputs.past_key_values if use_cache else None
            if streamer: streamer.put(next_token.cpu())
```

| 行 | 讲解 |
|----|------|
| 284 | **已结束序列强制输出 EOS**：`finished=True` 的行不再真采样，直接填 eos_token_id。好处：① 不产生「结束后的胡言乱语」；② 所有序列步调一致，输出张量矩形整齐 |
| 285 | 新 token 接到序列尾部（完整 id 序列持续增长） |
| 286 | 换用本次 forward 返回的新 Cache（含刚拼进去的新 K/V）。`use_cache=False` 则每步全量重算（不推荐） |
| 287 | 流式回调：把新 token 推给 streamer（TextStreamer 会解码成文字、TextIteratorStreamer/CustomStreamer 会交给消费线程/队列） |

```python

                finished |= next_token.squeeze(-1).eq(eos_token_id)
                if finished.all(): break
        if streamer: streamer.end()
```

|----|------|
| 288-290 | 更新结束标记（`|=` 按位或：一旦 EOS 永远置 True）；**全部**序列都结束时提前 break（省掉无效循环） |

```python
        return input_ids
```

| 行 | 讲解 |
|----|------|
| 292-293 | 特殊选项：把（增长后的）Cache 也返回给调用方——**多轮对话增量续写**时可用（避免重算整段历史）。默认只返回完整 id 序列 `[B, P+N]`，调用方自行切掉 prompt 部分得到回复 |

### 2.1 一次生成的完整时间线（B=1）

```
第 0 步: past_len=0, forward(prompt)         → Cache=P 层 K/V，选第 1 个新 token
第 1 步: past_len=P, forward(1 个新 token)    → Cache=P+1，选第 2 个
第 2 步: past_len=P+1, forward(1 token)      → ...
...
遇到 EOS → finished=True → 后续步强制填 EOS → 全部结束 → return [1, P+N]
```

### 2.2 与 HF generate 的关系

| | HF GenerationMixin.generate | MiniMind 手写版 |
|--|------------------------------|-----------------|
| Cache 格式 | DynamicCache 对象 | 裸 tuple 列表 |
| 功能 | 极全（beam、guidance、logits processor 链…） | 精简（sample/greedy + 四种惩罚/截断） |
| 代码量 | 数千行 | 32 行 |
| 学习价值 | 低（黑盒） | **高（每一步可见）** |

因为 Model 层会拦截 DynamicCache（216 行 `hasattr(past_key_values,'layers')` 检查），手写 generate 是本模型最稳的生成入口。

## 3. 采样参数的调法速查

| 现象 | 调整 |
|------|------|
| 回复重复绕圈 | `repetition_penalty=1.1`，或降 temperature |
| 输出呆板保守 | 升 temperature（0.85→1.0）、升 top_p |
| 胡言乱语 | 降 temperature、降 top_p、加 top_k |
| 需要确定输出（评测） | `do_sample=False` 或 temperature→极小 |

## 4. 本篇小结

1. 生成循环 = **「只 forward 新 token + Cache 拼接」**，复杂度线性；`input_ids[:, past_len:]` 是增量解码的落点。
2. 采样链顺序：**温度 → 重复惩罚（正除负乘）→ top-k → top-p（前缀和+右移掩码修正）→ multinomial**。
3. EOS 管理：`finished` 位图 + 强制填 EOS + 全结束才 break，保证 batch 输出整齐。
4. streamer 三回调：put(prompt)、put(逐 token)、end()——是所有流式 UI 的数据源。
5. `return_kv` 支持把 Cache 交还调用方做多轮续写。

# 00 - 项目总览

> 本篇是整个仓库的「地图」。读完它，你就知道每个文件是干什么的、训练一个完整模型的流程顺序、以及怎么把项目跑起来。后续每篇精读文档都会回到这张地图上定位自己。

## 1. 一句话理解 MiniMind

MiniMind 的目标是：**让你在个人 GPU 上，用几百行能逐行读懂的代码，把一个现代 LLM 从零训练出来**。

- 主线模型约 64M 参数（MoE 版约 198M 激活 64M），结构完全对齐 Qwen3 / Qwen3-MoE 生态。
- 所有核心算法（注意力、MoE、DPO、GRPO、PPO、蒸馏……）都是 **PyTorch 原生手写**，不调用 `trl`、`peft` 等封装库——这正是它作为学习材料的价值：你能看到每一个数学公式落到代码上的样子。
- 全部训练脚本总计约 4400 行，本 docs 目录会**逐行**讲完它们。

## 3. 训练全流程（阶段依赖图）

```
                       ┌────────────────────────────┐
                       │ train_tokenizer.py (可选)   │  仓库自带词表，一般跳过
                       └────────────┬───────────────┘
                                    ↓
   pretrain_t2t.jsonl ──→ train_pretrain.py ──→ out/pretrain_768.pth     （学语言：.next-token）
                                    ↓
   sft_t2t.jsonl ──────→ train_full_sft.py ──→ out/full_sft_768.pth     （学对话：只对 assistant 部分算 loss）
        │                    │    └── (可选) train_lora.py ──→ out/lora_xxx.pth    （冻结主干）
        ↓                    ↓
   dpo.jsonl ────→ train_dpo.py ─────────→ out/dpo_768.pth              （学偏好：chosen > rejected）
   rlaif.jsonl ──→ train_grpo.py ────────→ out/grpo_768.pth             （RLAIF：奖励模型打分）
   rlaif.jsonl ──→ train_ppo.py ─────────→ out/ppo_actor_768.pth        （RLAIF：带 Critic 的 PPO）
   agent_rl.jsonl→ train_agent.py ───────→ out/agent_768.pth            （多轮工具调用 RL）
        ↓
   (可选) train_distillation.py：MoE 教师 → Dense 学生
        ↓
   推理：eval_llm.py / serve_openai_api.py / web_demo.py
   评测：eval_toolcall.py（工具调用）；C-Eval 等见 README
```

三个要点：

1. **权重链**：每个阶段默认 `--from_weight` 上一阶段的产物（如 SFT 默认基于 `pretrain`），权重都存在 `out/` 下，命名规则是 `{阶段名}_{hidden_size}[_moe].pth`。
2. **MoE 分支**：任何阶段加 `--use_moe 1` 就切换到 MoE 版本，权重文件名自动加 `_moe` 后缀，与 Dense 版互不干扰。
3. **RL 三个脚本**（DPO/GRPO/PPO）互相独立，都以 `full_sft` 为起点，选一个跑即可；`train_agent.py` 是 GRPO 思想的多轮工具调用扩展。

## 4. 模型规格（默认 Dense 配置）

| 参数 | 值 | 出处 |
|------|-----|------|
| hidden_size | 768 | `MiniMindConfig` 默认 |
| 层数 | 8 | 同上 |
| 注意力头 | 8 个 Q 头 / 4 个 KV 头（GQA，每 2 个 Q 头共享 1 组 KV） | head_dim=768/8=96 |
| FFN 中间维 | ceil(768×π/64)×64 = 2432 | π 缩放公式 |
| 词表 | 6400 | tokenizer.json |
| 最大位置 | 32768（RoPE theta=1e6） | `max_position_embeddings` |
| 精度 | 训练 bfloat16 混合精度；保存 fp16 | 各 trainer 脚本 |

参数量口径：LoRA 之外的「全量微调」每个阶段都是对整个模型做 AdamW 更新，这正是 "full_sft" 名字的含义。

## 5. 依赖与版本陷阱（requirements.txt）

关键依赖与版本，踩坑点直接写在注释里：

| 包 | 版本 | 作用 / 注意 |
|----|------|-------------|
| **torch** | 未锁（README 建议 2.x） | 唯一没写进 requirements.txt 的核心，需按自己 CUDA 版本装 |
| **transformers** | ==4.57.6 | 提供 PreTrainedModel 基类、AutoTokenizer、chat template。**不要乱升到 5.x**——模型里专门为 5.x 写了兼容分支（见 01-整体架构 的 RoPE buffer 重算、convert_model 的写法兼容），但主线在 4.x 上验证 |
| datasets | ==3.6.0 | 加载 jsonl 数据。所有 trainer 都 `import datasets`，这是为了规避 **Windows 下 pyarrow/torch 的 DLL 冲突**（issue #771），必须最先 import |
| numpy | ==1.26.4 | pyarrow 兼容性问题：numpy 2.x 会崩 |
| pyarrow | >=15,<26 | 同上，锁上限 |
| swanlab | ==0.9.8 | 训练可视化。代码里 `import swanlab as wandb`，API 与 wandb 完全兼容，国内访问友好 |
| jinja2 | ==3.1.2 | 渲染 chat_template |
| streamlit | ==1.50.0 | WebUI |
| fastapi/uvicorn | 0.120.1 / 0.38.0 | API 服务端 |
| openai | ==1.59.6 | 客户端 SDK（chat_api.py / eval_toolcall.py 用） |
| 其余（jieba/flask/simhash/...） | — | 主要服务于官方数据清洗流程，本项目代码本体不直接用 |

## 6. 数据集下载

按 `dataset/dataset.md` 的说明，把数据文件下载后放进 `dataset/`：

| 文件 | 用途 | 规模量级 |
|------|------|----------|
| `pretrain_t2t_mini.jsonl` / `pretrain_t2t.jsonl` | 预训练（{"text": ...}） | mini 约 0.3GB |
| `sft_t2t_mini.jsonl` / `sft_t2t.jsonl` | SFT（{"conversations": [...]}） | mini 约 10 万条 |
| `dpo.jsonl` | DPO（chosen/rejected 成对） | 数万条 |
| `rlaif.jsonl` / `rlaif-mini.jsonl` | GRPO/PPO（prompt 为主） | mini 1 万条 |
| `agent_rl.jsonl` / `agent_rl_math.jsonl` | Agentic RL（带工具与 gt 答案） | — |
| `lora_medical.jsonl` 等 | LoRA 领域数据 | — |

下载渠道：HuggingFace（`jingyaogong/minimind_dataset`）或 ModelScope（`gongjy/minimind_dataset`）。

## 7. 实操指南（最小可跑通路径）

```bash
# 1) 环境
conda create -n minimind python=3.10 -y && conda activate minimind
pip install torch --index-url https://download.pytorch.org/whl/cu121   # 按自己的CUDA选
pip install -r requirements.txt

# 2) 数据：下载 sft_t2t_mini.jsonl、pretrain_t2t_mini.jsonl 放进 dataset/

# 3) 预训练（单卡约 1 小时）
python trainer/train_pretrain.py

# 4) SFT
python trainer/train_full_sft.py

# 5) 对话试玩
python eval_llm.py --model_path out --lora_name None

# 6) (可选) 起API / WebUI
python scripts/serve_openai_api.py
streamlit run scripts/web_demo.py
```

> 注意 trainer 脚本里默认路径都写成了 `../dataset/...`、`../out`——即默认工作目录是 `trainer/`。如果你在仓库根目录运行，需要传 `--data_path dataset/...` 等参数，或者 `cd trainer` 后再跑。

## 8. 阅读源码的推荐顺序

1. `model/model_minimind.py` —— 一切的核心（对应 docs 01-模型架构/ 八篇）
2. `dataset/lm_dataset.py` —— 数据怎么变成 token（对应 docs 03-数据集/）
3. `trainer/train_pretrain.py` —— 最简单的训练骨架（对应 docs 04-训练/02）
4. `trainer/train_full_sft.py` —— 和 pretrain 几乎一样，差异在数据（对应 04-训练/03）
5. RL 三篇按兴趣选：DPO（最简单）→ GRPO → PPO → train_agent
6. 推理链：`eval_llm.py` → `serve_openai_api.py` → `web_demo.py`
